Streaming Live RAG vs. Normal Sequential RAG
Architectural, latency, and capability comparison between Theme 4 Streaming Live RAG and a Classic Sequential RAG pipeline.
Dimension ⚡ Streaming Live RAG (Theme 4) ⚪ Normal Sequential RAG
Retrieval Timing Speculative In-Flight: Dispatches vector search in background while speaker is still talking (Gate G2). Post-Utterance: Waits until speech completely concludes before beginning any retrieval.
Perceived Latency Sub-second (~200–500ms): Massive head start (+20s to +30s) finishes searches before speech ends. High (3,000–6,000ms+): User waits through sequential decomposition, search, and synthesis after speaking.
Intent Decomposition Concurrent Progressive Beams: Identifies multiple sub-intents and queries vector store simultaneously in real time (Gate G3). Monolithic Batch: Breaks utterance down into sub-queries sequentially after audio finishes.
Reasoning Context Continuous Thought: Live reasoning stream without resetting context across clauses. Discrete Restarts: Each query starts from scratch without in-flight continuity.
Query Cache Instant (<5ms): Fast in-memory cache returns 100% grounded answers instantly for identical queries. Repeated Compute: Re-embeds, re-searches, and calls LLM on every query repeat.
Chit-Chat & Reformat Zero Retrieval: Suppresses vector calls for greetings (C2) and reformats existing answer without new search (C4). Unnecessary Searches: Executes vector search on every greeting or reformat request.
Real Concurrent Execution Arena Cache Bypassed
Fires both pipelines simultaneously as two isolated, parallel sessions with query caching strictly bypassed. Live Voice Mode: Speak into your microphone — partial speech chunks stream live into both pipelines. Live RAG executes speculative retrieval in-flight while you speak; Normal RAG waits until your speech concludes.
